# 星图

**把「不懂」画出来。**

一个按需生长的知识宇宙：你问一个问题，它长成一颗星；你点开星上任意一个你再没听懂的概念，它就当场再拽出一个新的问题节点。所有的讲解都是大语言模型在**你点开它的那一刻**现写的。

> 别人的做法是把答案生成出来。这个项目想做的事，是把你还**不懂**的那一部分先摆到台面上。

**在线体验（不用装任何东西）：** https://huanjianwanzhao.github.io/
> 打开后按提示填一次自己的 DeepSeek API Key（只存在你的浏览器里，见下方「合规」）。

## 它解决什么问题

课程作业的题目是「做一个网站」。我最初想做的是「把很多课程的 AI 生成讲义收集起来」——被自己否决了：那不解决任何问题，只是把已经满地的内容再抄一遍。

真正的痛点是：**AI 现在已经能回答任何问题了，但你读完一段流畅的回答，往往还是不知道自己是哪里没懂。** 因为答案是以「成品的形状」给出来的——从定义讲起、一路铺到结论，读者没有地方把自己的空白插进去。

所以星图换了个方向：**问题在前，概念在后。**

- 你输入的是一个**问题**，不是一个知识点。问题节点在图上是一个圆角矩形，带一个 ✦。
- 讲义里每出现一个**你没听懂的概念**，那个概念会从问题里长出去，变成一个新的、可以被继续点开的问题。
- 概念节点之所以存在，**只因为它是被你问出来的**。这个图不是知识图谱——它是你这一个人的、这一次探索的足迹。
- 于是「我不懂」第一次有了形状：哪一支长得很深、哪一支点到为止，一眼就能看见。

## 三种打开方式

### 1. 在线体验版（零安装）

打开上面的链接，按提示填一次自己的 DeepSeek API Key。页面**直接在浏览器里调用模型接口**，没有服务端，没有任何东西被上传到第三方（除了那次本来就要发给模型服务商的请求）。星图和讲义存在你浏览器的 localStorage 里。

- 对应文件：`prototype/03-live.html`（单文件，可以下载下来双击直接用）
- 换电脑、换浏览器、清一次浏览器数据 = 回到初始状态。

### 2. 本地完整版（推荐，数据落盘）

```bash
git clone https://github.com/huanjianwanzhao/huanjianwanzhao.github.io.git
cd huanjianwanzhao.github.io/prototype

# 需要 Node 22 以上（用到内置的 node:sqlite）
copy config.example.json config.json     # 然后填入你的 API Key
start-server.bat                          # Windows；或 node server.js
```

浏览器打开 http://localhost:5173 —— 打开的那个页面是 `prototype/星图.html`。

这一版多出来的东西：

- API Key 不出现在网页源码里，只在本机服务端读 `config.json`；
- 星图结构、讲义正文、每一次生成的用量，全部写进本机一个 SQLite 文件 `star.db`（5 张表），刷新、关机、换浏览器都不丢；
- 讲义有**四层缓存**（前端 → 服务端内存 → SQLite → 模型），同一个概念第二次问不用再花钱。

### 3. 离线版（断网 / 没有 Key 也能看）

`prototype/02-app.html` 双击就开，走内置样例数据，不联网。适合演示前确认机器的显示效果。

## 界面上的几个决定

| 决定 | 为什么 |
| --- | --- |
| **问题节点是圆角矩形 + ✦，概念节点是胶囊** | 眼睛必须先分清「这是我问的」和「这是它给我的」。这是整个界面的第一原则。 |
| **层级用「实心程度」表达，不用边框** | 恒星是实心发光的，行星半透明，卫星几乎只剩描边。早先的版本给根节点套了两道同心圆环，在暗背景上读起来像焦点框而不像星，已经删掉换成一层径向柔光。 |
| **首页有两个入口：我想弄懂一个原理 / 我只想知道一个事实** | 这是这个项目里最重要的一个区分。**「不知道」和「不懂」是两件事**：前者缺一个事实，一行字就能补齐，这个需求已经被搜索和聊天机器人解决了；后者缺一整套结构，这才是值得可视化的东西。用「不懂」的模具去答「不知道」，模型会被迫先讲三百字的悬念，最后才把答案说出来。所以事实走一条单独的极短通路（第一行就是答案），并且给一个「那它为什么会这样 →」的按钮，点下去同一个格子原地升级成一份完整讲义。 |
| **搜索框同时也是提问框** | 搜了没搜到，最后一行永远是「问一个新问题：『你刚打的字』」。找一个东西和问一个东西，本来就是同一个动作。 |
| **合并两个星团 = 长出双星，而不是吞并** | 如果把一个星团并进另一个，那个你亲口问出来的问题就消失了——和「把不懂可视化」直接矛盾。所以合并后会新建一个「桥」节点当新的根，两个原问题都留下，中间那条边是它们之间的关系；桥上的讲义专门讲共同点、差别、谁先谁后。合并是唯一不可逆的操作，因此给了撤销。 |

| **手动连上的两条线，要能说出它俩是什么关系** | 合并是「两个星团」，连一条线是「两个节点」——后者才是日常。连上之后让模型写一句 `短名 + 一句话`（「优化与约束的搭档：正则化为梯度下降的更新方向加惩罚项」），这句话写进边上、也写进导出文件。**星图的边以前全是 AI 生成的父子树，从这一步开始，边变成了用户能写的一行字。** |

## 从 Obsidian 借来的三件事

Obsidian 解决的是「存哪里、怎么连」，不解决「我到底哪里不懂」。它的图谱是你已经想清楚之后的产物，星图的图是你还没想清楚时的脚手架。所以整份生态里能借的只有三样，而且都借成了别的形态：

| 借来的 | 星图里的形态 |
| --- | --- |
| **`[[双链]]` 与反向链接** | 顶栏「航线」模式下依次点两个节点 → 连出一条手动边 → 面板上出现「你亲手连上的」这一段，点一下让 AI 说清它俩是什么关系；反向查询两个方向都有（在 A 的面板里看得见 B，在 B 的面板里也看得见 A）。 |
| **卖出出口** | 顶栏「导出」：把整张星图打包成一个 `.md` 文件夹（每个星团一个目录、每个节点一个文件、YAML frontmatter + `[[链接]]`、每团一份 `索引.md`、根上一份 `README.md` 和 `星图.json`）。**用 store-only ZIP 手写实现，零依赖**，解压后 Obsidian 直接当库打开。 |
| **「最近」这一类时间视角** | 设置菜单里的「最近弄懂的」：直接读服务端 `generations` 表（这张表本来只用来做统计，一直闲置），把「什么时候、在哪个星团、点开了哪个概念、自检过没过」列出来，点一条就跳回那个节点。 |

没有借的：插件系统、文件夹即库、把关系图谱当卖点、同步。星图是 Obsidian 的上游——它负责「我到底哪里不懂」，Obsidian 负责「懂了之后存哪儿」。

## 讲义长什么样，是可以换的

这是第四件从 Obsidian 借来的东西，但它借的是**「用户能改」这件事本身**，不是某个功能。

同一道题，文科生要的是类比，物理系要的是先说公式，考前十分钟要的是一句话结论。所以「讲义长什么样」不该由我一次性定死。服务端目录 `prototype/templates/` 里的每个 `.rules` 文件就是一副**模具**——它不是模板（模板是填空），它改的是**说话方式**：先说什么、后说什么、不许说什么、哪里必须给数字。

页面里在「菜单 → 模具」换一副，下一次生成的讲义就换一个形状。改完文件**刷新即生效**，不用重启服务。

已有的四副：

| 模具 | 它改了什么 | 代价 |
| --- | --- | --- |
| `00-默认` | 什么都不加，就是原来那一版 | —— |
| `01-类比优先` | 先落在一件日常小事上，`##BOUNDS` 只写「这个类比你哪里塌掉」 | 类比总会漏 |
| `02-公式优先` | 顺序改成 `##FORMULA → ##READ → ##SYM(≥3) → ##MECH`，`##MIS` 必须是代入数字才暴露的错 | 没有公式的概念会显空 |
| `03-最短路径` | 全文 150 字以内、结论先行、`##CHILD` 最多 2 个、不写 `##MIS` | 它刻意不讲透 |

**为什么改坏模具也不会把网站搞坏：** 13 个标签的行协议、自检的 17 项、解析和渲染，全部在服务端和前端里写死，模具的正文是**追加在协议后面**的（后说的写法定得更大声，所以它真的改得动），但它**没有能力删掉任何一条协议**。最坏的结果是这份讲义难看、自检挂一行 `##CHECK fail`，而不是页面崩掉。写一个新模具 = 复制一个文件、改正文、存成 `04-xxx.rules`，文件名就是显示名。

同一套机制在客户端直连模式里退化成一个内置默认模具——在线版读不到服务端的文件，这一点在「关于 · 合规」里写明了。

## 它是怎么做的

**零依赖。** 没有 `package.json`，没有 `node_modules`，没有前端框架。服务端只用 Node 内置的 `http` / `fs` / `path` 和内置 SQLite（`node:sqlite`）。前端是一个自包含的 HTML 文件。

**三层结构：** 浏览器 → 本机 Node 服务（127.0.0.1） → 模型接口（OpenAI 兼容，`stream: true`）。

**为什么用行协议，而不是 JSON？** 模型被要求按一种**逐行的自定义协议**输出，一共 13 种内容标签（`##COMMON` `##INSIGHT` `##FACT` `##SCENE` `##MECH` `##FORMULA` `##READ` `##SYM` `##BOUNDS` `##MIS` `##LIST` `##CHILD` `##TITLE`），最后以 `##CHECK ok` 收尾。

原因是它要**边流边渲染**：JSON 必须等整个对象闭合才能解析，而行协议每收到一行就能立刻画上去，用户看到的是「正在长出来」而不是一个转圈。同时它给了自检一个极低成本的抓手——不用解析、不用再调一次模型，扫一遍字符串就能判断这份讲义是不是空的、超长的、或者把答案藏到了最后。

**约束写在提示词里，不写在代码里。** 服务端有一份 29 条硬规则的 `PROTOCOL`（行协议 + 硬性规则 + 关系词表，用户碰不到），客户端镜像一份完全一致的（离线直连模式用）；模具的正文追加在它后面，另外还有一套**零 API 成本的字符串自检**（17 项）。不合格时讲义末尾会打一行 `##CHECK fail …`，并记进本机的生成记录——**它不会自动重写**，重写与否由用户按右上角的 ↻ 决定。把「模型做得对不对」变成一个用户看得见的按钮，比假装系统能自我纠正要诚实。

## 实测数据

都是我实际跑出来、写进本机 `star.db` 的数，不是估算：

| 项 | 数值 |
| --- | --- |
| 累积生成次数 | 55 次，其中 47 次通过自检、8 次被拦下（`ok=0` 与 `problems` 非空完全一一对应） |
| Token 消耗 | prompt 39,421 / completion 24,509 / 命中缓存 20,224 |
| 库里的规模 | 6 个星团 / 50 个节点 / 48 条边 / 43 份缓存讲义 |
| 事实模式的长度 | 262 字符，答案在第一行（同一个问题走原理模式是 771 字符） |
| 布局算法 | 600 个节点算一遍 0.05 ms，没有二次爆炸 |
| 局部重排 | 61 个节点的星团里新增 40 个概念：原来整图补间 101 个节点，现在只补间那 40 个 |

## 边界与合规

这一节在网页上的「关于 · 合规」里也有，两处口径一致。

- **内容是 AI 生成的。** 每一份讲义、每一个概念名都由模型实时写出。这个项目**没有预置知识库**。
- **它一定会说错。** 自检只能拦住格式和空洞，**拦不住错误的知识**。请把它当成一个「把不懂变成可以追问的结构」的工具，而不是答案来源。
- **你的数据去了哪里。** 每次提问会把你的问题原文、当前节点名、同一星团里已出现过的概念名发给模型服务商；除此之外没有任何上传。本地版的星图、讲义、用量只写进本机的 `star.db`。页面不设 cookie，不接统计脚本。唯一的外部资源是排版公式用的 KaTeX（可选，CDN）。
- **凭据与部署边界。** `config.json` 里是**明文** Key，已经被 `.gitignore` 排除。本地服务只监听 `127.0.0.1`，且所有 `/api/*` 接口没有任何鉴权——**一旦挂到公网，它就等于一个任何人都能调用的开放模型代理**。要部署必须先加访问令牌、限流和 HTTPS。（在线体验版没有这个问题：它没有服务端，Key 在用户自己的浏览器里。）
