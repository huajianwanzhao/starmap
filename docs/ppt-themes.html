01 · 起点

我推翻了自己最初的想法

最初的设想

把很多课程的 AI 生成讲义 聚合成一个站。

听起来很完整，但它是一个静态的图书馆。

三个致命问题
  1. 内容由 AI 生成 → 谁都能做，没有护城河
  2. 学习产品的死穴不是没内容，是没人回来第二次
  3. 一个人两周生成不完「很多课程」
改为 按需生长：不预生成任何东西，深度由用户自己的疑问驱动。

04 · 空间结构

星团，与宇宙

一次提问 = 一个星团；所有星团共存于同一片宇宙。拉远是你的知识版图，拉近是某个具体问题。
径向树布局：先自底向上算出每棵子树的叶子数，父节点把角度扇区按比例分给孩子 —— 两条分支永远不会抢同一片空间。
星团之间自动分离：算出实际包围半径，相交就各推开一半；单团半径上限 820px，否则钻得越深越膨胀。
所有位移汇总成一次补间，并带令牌，防止连续下钻时多个动画互相打架。
早期版本只把某一层子节点摆成一圈，层与层之间没有约束 —— 第三层必然撞第二层。这是改了三轮才想对的。

05 · 交互

四种模式，各自有明确职责

模式做什么
阅读态右侧边栏读讲义，星图保持可见。节奏是 读 → 点 → 长 → 再读
聚焦模式默认开启。只显示你走过的路 + 当前节点的下一步 —— 星图只记录你的足迹
航线模式点两个节点把它们连起来。紫色是 AI 找到的，蓝色是你亲手连的
合并模式把一个星团拖到另一个上面，问「要不要合成一个问题」
不可逆的动作必须多一道门槛：平时拖动只是搬家，合并要主动开启模式、再确认一次。

06 · 生成契约

为什么用行协议，而不是 JSON

每收到一整行，就立刻渲染一行 —— 用户看到文字正在被写出来，而不是转圈等三秒
##COMMON  大多数人以为：……
##INSIGHT  其实……
##SCENE    一个不出现任何专业名词的画面（≤2 句，含具体数字或量词）
##MECH     它是怎么工作的（可多行）
##FORMULA  公式（用 Unicode 直接写，不用 LaTeX 反斜杠）
##READ     读作：……          ##SYM  符号 | 它是什么
##BOUNDS   它在什么时候失效   ##MIS  一个常见误解
##CHILD    子概念 | 它回答的下一个问题 | 关系词 | 为什么值得点进去
JSON 必须等整个对象闭合才能解析 —— 那就没有「边写边看」了。行协议是唯一能同时满足「流式渲染」和「结构化建图」的形状。

07 · 生成契约

七条硬规则，四条自动质检

七条硬规则
  1. 洞察必须反直觉（必须含转折词）
  2. 画面必须自足（不许出现专业名词）
  3. 公式必带读法与符号表
  4. 必须写失效条件
  5. 子概念最多 4 个，且必须是「下一个困惑」
  6. 禁止循环定义：画面 → 现象 → 最后才给名字
  7. 正文 ≤ 400 字
四条自动质检 · 零 API 成本
洞察里出现本节点名在下定义 → 打回
洞察 / 画面里出现其他概念名耦合 → 打回
画面里没有数字或量词不具体 → 打回
洞察里没有转折词不反直觉 → 打回
我没有靠「提示词写得更好」—— 我把两条质量标准变成了 四次字符串检查。质量不是靠祈祷，是靠可验证的契约。

12 · 工程真实性

我踩过、并且修掉的坑

子节点被挂两次：星团创建时预生成一批，打开讲义时又生成一批 → 根节点 8 个子节点、四对近义
小地图每帧重建 DOM：拖拽时每帧用 innerHTML 重建几十个圆点 → 明显卡顿
backdrop-filter 常驻：面板一直盖在运动的星图上，浏览器每帧重新模糊 → 主要延迟来源
星团之间会重叠：布局只保证团内不重叠，而星团会长大
readBody 用字符串拼接：HTTP 分片会把跨片的中文字符切坏 —— 小请求看不出来，星图快照一存就烂
check 是 SQLite 保留字：建表语法错误 → 数据库静默降级成「不持久化」，日志里只有一行
最后两个坑是做持久化才暴露出来的。它们不丢人 —— 它们是「这个系统真的跑起来过」的证据。

13 · 判断力

明确决定不做的

不做的原因
embedding 语义去重DeepSeek 没有 /embeddings 接口；当前规模下收益不值这个复杂度。代码保留但休眠，需要时可直接启用
节点级合并交互成本高，星团级合并已覆盖主要场景
读者水平设置多一个全局状态，收益不明显
公式「代入数字」只要公式、读法、符号表讲清楚就够
音频 TTS要再接一个服务，性价比低
能说清不做什么，比列一堆功能更有说服力 —— 被问到时，我陈述的是一个已经做过的判断，不是在辩解。

14 · 合规与伦理

边界是设计的一部分

凭据安全

API Key 只存在服务端，前端只拿得到掩码；
网页端可以配置，但 Key 只在浏览器 → 本机服务端之间传递一次；
服务端只监听 127.0.0.1，局域网内碰不到。

我意识到的风险

一旦挂上公网，/api/lecture 就是一个开放的模型代理，任何人找到网址都能刷我的额度。

所以：本机演示为主，公网必须加令牌 + 限流。

AI 生成内容一律标注来源与「请核验」；不使用他人数据、图片与字体，不涉及用户隐私数据。

结语
别人做的是内容生成，我做的是把「不懂」可视化。
同一个概念，从不同路径到达，看到的侧面不一样。这是知识图谱比传统教材强的地方。
我没有靠「提示词写得更好」，我把质量标准变成了可执行、可验证的检查。
自动化的前提是可撤销 —— 所以合并要二次确认，航线可以删。
